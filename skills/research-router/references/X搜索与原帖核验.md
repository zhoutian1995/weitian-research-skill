# X 搜索与原帖核验

## 两条链路

Grok X Search 用于发现帖子和候选 URL；xurl 用于搜索公开帖子以及回读同一帖子。Grok 模型访问授权与 X 用户 OAuth 是两套授权，不能互相代替。环境变量缺失不代表本机没有 OAuth；有密钥也不代表当前请求有权限。

先发现可用工具及其帮助，再选择已授权入口。xurl 是可选的独立核验工具，当前资料搜索.py 仍调用 last30days，不自动调用 xurl 或继承其认证。不得把生成路由清单报告为已完成搜索。

## 有界只读流程

1. 确认 xurl 版本及显式 App。使用操作者指定的 App，不随意依赖 default，不读取或打印认证文件。
2. 用 `xurl --app APP_NAME whoami` 验证身份；输出只保留成功与否，不把个人资料放进调研结果。
3. 用 Grok X Search 发现候选，或 `xurl --app APP_NAME search "查询词" -n 10` 小样本搜索。命令参数以本机 help 为准。搜索时间窗应明确，不能声称覆盖 API 不支持的历史范围。
4. 对入选帖子运行 `xurl --app APP_NAME read POST_ID_OR_URL`。检查返回 ID 等于请求 ID，正文非空，作者和发布时间齐全；互动量缺失就标缺失。
5. 按帖子 ID 去重，并做事件级聚类；转发同一个声明不是独立佐证。对照任务时间窗，以源时间为准。
6. 记录原帖 URL、ID、作者、发布时间、正文摘录、回读状态、采集时间和核验缺口。作者观点、数字、产品宣传均需注明归属；成功回读不等于独立事实核验。

Grok 无引用或原帖回读失败时，仅保留为线索，不允许用模型综合回答补造帖子正文、作者或日期。404/删除、403/受限、401/认证、429/限流和真正的空结果必须分别记录；错误原因无法确认就标未知。

## 401 与失败处理

先检查版本、显式 App 和授权绑定，不直接推断为付费权益不足。已知旧 xurl 可能出现 Token 与 App 凭据错位；本机既有修复使用 v1.3.1，不能据此断言所有版本或所有 401 都相同。不要自动删除 App、展示 Token、覆盖认证库、反复重新登录或降级二进制。需要修复时读取本机维护记录并在授权范围内处理。

单项读取失败最多重试两次；401/403 不盲目重复，429 按返回的等待信息停止或稍后再试。调用成功与否、耗时和有效原帖数分开记录，长期稳定性必须依靠连续观测。

## 来源范围

若用户明确要求仅 X 原帖，失败后不能用博客、RSS、GitHub 或旧稿补位；帖子中的外部链接也不自动展开。若是普通多平台研究，仍保留其他平台，不能把某份日报的 X-only、48 小时、条目数和投递规则变成全局限制。

## 本机与公开包

App 名、CLI 绝对路径、日报接收人和凭据位置属于部署配置，不固定为所有用户的默认值。运行时按用户的本机记录选择。搜索不授予发帖、私信、关注、投递日报或安装修复工具的权限。
