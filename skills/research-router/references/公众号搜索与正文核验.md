# 公众号搜索与正文核验

适用于国内行业解释、产品案例、规则背景及经验文章。公众号文章不天然代表用户需求：厂商介绍标记为 `vendor_claim`，作者亲身经历与官方规则分别归类，不把营销数字写成已证实事实。

## 从发现到原文

1. 用当前可用的浏览器 Skill（本机为 Ego Lite）打开搜狗微信文章搜索：`https://weixin.sogou.com/weixin?type=2&query=<编码后的关键词>`。先看标题、账号和摘要，只挑与问题相关的少量文章。
2. 用页面上实际存在的链接进入原文。点击未跳转时检查当前页面/新标签，再使用观察到的完整链接导航；不构造签名链接，不逆向接口。备用入口是公开网页搜索 `site:mp.weixin.qq.com 关键词` 或用户给出的文章链接。
3. 等正文和作者信息加载，再读取可见文章内容。确认标题、账号、页面日期及正文；页面快照可能截断，单次快照成功不代表全文完整。图文中的图片文字、折叠内容未读取时应标记缺口。不要把页面菜单、推荐、评论混入文章正文。
4. 遇到登录或验证码交给用户操作；风控时停止当前入口，记录受限状态。不要连续重试、批量翻页或采集账号全部历史。公开文章可读时无需先购买 API 或要求登录。

## 保留证据来源

- 保存 `original_url` 和 `final_url`；仅在页面实际提供并核验后记录 `canonical_url`。带签名的跳转地址标记 `url_status: signed_persistence_unverified`，保留原样，不删参数冒充永久链接。
- `published_at_raw` 保留页面原始日期文字，`published_at_source` 标记出处。搜索页日期另存 `published_date_from_search`，不能当成已核验的文章发布日期；页面无年份时不猜年份。
- 作者可从可见账号名或文章 author 元数据核对；保存为 `author`，采集器的 `account` 也可由规范化脚本接收。
- `visible_text` 仅代表本次读到的文字。用 `body_status` 区分 `visible_text_only`、`truncated` 和已核验的 `complete`。缺互动量填空，并在 `limitations` 记录，不能填零。
- 用 `captured_at` 或 `retrieved_at` 记录实际采集时间。元数据、全文或链接持久性尚未核验时使用 `status: partial`。
- 去重优先使用实际文章 ID 或已核验的规范链接；正文哈希作补充。同标题不能直接视为同一篇；多个转载不能算独立佐证。

## 规范化和验收

`python3 scripts/证据规范化.py <raw.json> --platform wechat --output <允许的证据归档绝对路径>` 支持单条文章对象及数组。它只整理已有记录，不负责搜索、读取或核验；`stats.complete` 仅表示标题、平台、链接三项齐全，不能当成全文/事实核验通过数。

原始正文、带签名链接和测试证据保留在用户的知识库，不加入公开 Skill 仓库。遵守用户的存储规则。

验证需分别记录搜索耗时、原文读取结果、元数据缺失和链接有效性。已有一次单篇浏览器验证成功，搜索页约 9 秒；这不代表全流程耗时或长期稳定性。需要对比 API 时再做多个主题的小样本测试，以有效原文数量和人工介入次数评估，不能只看返回链接数量。
